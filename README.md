# Webまなび帳

これまでに作った自作アプリ（筋トレ記録カレンダー、画像かんたん編集、抽選ツール、リバーシ、Gitまなび帳）で使った Web 技術やサービスを学ぶためのアプリです。
Service Worker や Canvas API などの技術ごとに、やさしい解説と「自分のアプリでの使われ方」（コードの抜粋つき）を読めて、クイズとフラッシュカードで復習できます。

**▶ アプリを開く: https://trendgoing-stack.github.io/web-manabi/**

登録やログインは不要です。無料で使えます。

## できること

- **探す** — 技術名でも、カタカナ・ひらがな・英字でも探せます。カテゴリ、レベル（入門／中級）、アプリで絞り込めます。検索語が空のときは、カテゴリ一覧と「アプリから探す」を表示します
- **技術の解説** — 「何か」「なぜ必要か」「仕組み」「落とし穴・iOS Safari での注意」を、初心者向けのやさしい言葉で説明します。説明文の中の用語をタップすると、意味をその場で確認できます
- **自分のアプリでの使われ方** — その技術を、どのアプリのどのファイルでどう使ったかを、コードの抜粋つきで紹介します。抜粋は「コピー」でき、GitHub の該当する行や最新版も開けます
- **ミニデモ** — 画像の縮小（Canvas）、乱数の比較、共有シート、指での描画、効果音を、その場で試せます
- **アプリ** — アプリを選ぶと、そのアプリで使った技術の一覧をカテゴリ別に見られます。「このアプリの技術でクイズ」もできます
- **学ぶ**
  - **クイズ** — 技術名から説明を、説明から技術名を、アプリ名から使った技術を 4 択で答えます。1 セット 10 問。範囲（カテゴリ・アプリ）とモード（通常／苦手を復習／今日の復習）を選べます
  - **フラッシュカード** — 表に技術名、裏に説明と使ったアプリ。裏面で「覚えた」「まだ」を選びます（左右のスワイプでも選べます）
  - **今日の復習** — 答えた結果から次に復習する日を決め（ライトナー方式）、その日になった項目をまとめて復習できます
  - **用語集** — 五十音順に並んだ用語を検索できます
- **マイ** — お気に入り（並べ替えできます）、閲覧履歴、項目ごとの自分用メモ、学習状況（箱ごとの件数、カテゴリ別の正答率）をまとめて見られます

## iPhoneで使う

ホーム画面に追加すると、アプリのように全画面で使えます。一度開けば、電波のない場所でも起動します（外部サイトへのリンクを除く）。

1. **Safari** で上のリンクを開く
2. 画面下の共有ボタン（□に↑のアイコン）をタップ
3. 「ホーム画面に追加」をタップ

> [!IMPORTANT]
> Safariで開いた場合とホーム画面から開いた場合では、お気に入りやメモ、学習記録が**別々に保存**されます。
> 普段使うときは、ホーム画面のアイコンから開くようにしてください。
> 移したいときは、設定の「エクスポート」で書き出し、もう一方で「インポート」できます。

AndroidやPCでも、ChromeやEdgeなどのブラウザで同じように使えます。

## アプリの更新

新しいバージョンや学習データの追加が用意できると、アプリを開いたときに画面の上部に
**「更新があります（タップで再読み込み）」** と表示されます。
タップすると最新版に切り替わります（お気に入りやメモ、学習記録はそのまま残ります）。表示されないときは、すでに最新版です。

いま使っているアプリと学習データのバージョンは、設定画面のいちばん下で確認できます。

## データについて

- お気に入り・閲覧履歴・メモ・学習記録・設定は**お使いの端末の中だけ**に保存されます。サーバーには送信されないので、ほかの人に見られることはありません
- そのため、**機種変更やブラウザのデータ削除をするとデータは消えます**。設定の「エクスポート」で定期的にバックアップを取っておくと安心です
- 設定の「すべてのデータを削除」で、このアプリのデータだけをまとめて消せます（同じサイトにあるほかのアプリのデータは消えません）
- アクセス数の計測に [GoatCounter](https://www.goatcounter.com/) を使っています。送るのはアプリを開いたときの 1 回だけで、送る内容は決まったページ名と画面の幅などだけです。クッキーは使わず、見た項目や検索した言葉、メモの内容が送られることはありません。設定の「アクセス解析を送信しない」で止めることもできます

## ご利用にあたって

- 説明文はすべてオリジナルの要約です。正確な仕様は、各項目の参考リンク（公式ドキュメントや MDN）で確認してください
- ブラウザの対応状況やサービスの仕様は変わることがあります。確認してから一定の日数（Claude Code の項目は 90 日、ほかは 180 日）がたった項目には「要再確認」のバッジが付きます
- コードの抜粋は、記載したコミット時点のものです。最新版とは異なる場合があります
- Git や GitHub の操作は扱っていません。[Gitまなび帳](https://trendgoing-stack.github.io/git-manabi/) で調べられます

## はじめて使うときは

「アプリ」タブで、よく使っているアプリを選んでみてください。そのアプリで使った技術が並んでいるので、気になるものから読むのがおすすめです。
読んだらクイズやフラッシュカードで確かめ、「今日の復習」で少しずつ覚えていきましょう。

## 開発者向け

ビルド不要の静的サイトです（バニラ JavaScript の ES Modules ＋ HTML ＋ CSS。外部ライブラリや CDN は使いません）。ファイル構成や開発用ツールは [DEVELOPMENT.md](DEVELOPMENT.md)、学習データの書き方は [CONTENT.md](CONTENT.md)、実機確認のチェックリストは [TESTING.md](TESTING.md) にあります。

### 手元で動かす

```bash
python -m http.server 8766
```

http://localhost:8766/ を開きます（ファイルを直接開くと動きません）。手元では Service Worker を登録しないので、編集がすぐに反映されます。Service Worker を試すときは http://localhost:8766/?sw を開きます。

### 公開（GitHub Pages）

`main` ブランチの `/ (root)` を GitHub Pages で公開しています。`main` に push すると、数分で公開中のアプリに反映されます。

### 更新するとき

利用者の端末には Service Worker がキャッシュしたファイルが表示されるため、**何かを変えたら必ず `sw.js` の `VERSION` を上げてから push** します（上げないと利用者に届きません）。

- **学習データ（`data/`）を変えたとき**
  1. `data/meta.json` の `dataVersion`（例：`2026.10.01-1`）と `counts` を更新する
  2. `sw.js` の `VERSION` と `js/config.js` の `APP_VERSION` を同じ値に上げる（例：`1.0.0` → `1.0.1`）
  3. `node tools/validate-cli.mjs` でエラーが 0 件であることを確認する（ブラウザで `tools/validate.html` を開いても同じ）
  4. push する
- **アプリ本体（HTML・CSS・JS）を変えたとき** — `sw.js` の `VERSION` と `js/config.js` の `APP_VERSION` を上げます。ファイルを追加・削除したときは `sw.js` の `SHELL` も直します（`node tools/validate-cli.mjs` が漏れを知らせます）。出題の仕組みを変えたときは `node tools/test-logic.mjs` も実行します
- **動作や内容を確かめた項目があるとき** — その項目の `lastReviewed` に確認した日、`verifiedNote` に確認した内容（例：`iOS 18.1 実機で確認`）を書いて、学習データと同じ手順で公開します。確認日から一定の日数がたつと「要再確認」のバッジが付きます
- **対象アプリを更新したとき（コード抜粋の `commitSha` の更新）**
  1. 参照用フォルダ（`C:\Users\KATSUYA\manabi-sources\`）の各リポジトリを最新にする（参照用フォルダの更新は作者が行う）
  2. `node tools/snippets.mjs check C:/Users/KATSUYA/manabi-sources` で点検する
  3. `△`（HEAD でも同じ内容）だけなら `node tools/snippets.mjs update C:/Users/KATSUYA/manabi-sources` で `commitSha` をまとめて更新する。`▲`（内容が変わった）は `extract` で抜粋を取り直し、使われ方の説明も見直す
  4. 学習データを変えたときと同じ手順で、版を上げて公開する

詳しい手順と、参照用フォルダで許可・禁止する操作は [CONTENT.md](CONTENT.md) にあります。
